The problem

Both sides fly blind between reviews.

Performance reviews happen once or twice a year. In the months between, managers can't see growth and engineers forget what they're being graded on. Both ends of the relationship lose signal.

For the manager

Annual reviews are too coarse

12 months condensed into a one-hour conversation. Memory bias, recency bias, and missing data dominate.

Daily standups are too narrow

"What did you do yesterday?" tells you about today, not about a 6-month skill trajectory.

Skill growth is invisible

No view of which skills each engineer is sharpening, on which projects, at what rate.

For the engineer

KPIs are forgotten by week three

After the review meeting ends, the goals go in a doc that nobody reopens. Six months later, the engineer is shocked at what they're being graded on.

No feedback loop, no motivation

Hard work doesn't feel like progress when no one — including yourself — can see it. Constant, visible signal beats annual verdicts.

"Where do I actually stand?"

Engineers can't see which skills they're growing, where they're plateauing, or how close they are to the next level. Self-improvement needs a mirror.

Engineers already log hours and write daily notes. The data exists. What's missing is a system that turns those entries into a continuous, two-way picture of growth — one the manager and the engineer can use every week.

The solution

A weekly & monthly dashboard, gamified.

1XP per logged hour. Each timesheet entry earns experience points in the relevant skill bucket.

2Per-engineer skill set. ICs and Leads are graded on different skills — no one is judged on dimensions they don't own.

3Levels & badges. Eight levels per skill, plus weekly badges (Deep Focus, Multi-skilled, Skill Up, Cross-Trainer).

4One self-contained file. A single HTML dashboard per period. Opens in any browser. Email it, host it, archive it.

Outputs

  • • Per-engineer card: hours, level, radar, badges
  • • Project-hours bar chart
  • • Team skill-coverage heatmap
  • • Drill-down: top projects, last review notes

How it works

Three stages. No new tools for the team.

01

Fetch

Pull timesheet entries from the existing Google Sheet and engineer email threads via the Google Workspace API. Read-only, no scraping, no extra logging burden on the team.

02

Classify

Each entry's description is tagged with one or more skills (Coding, Mechanical, Testing, …). v1 uses keyword rules; v2 swaps in a Claude Sonnet pass for nuance.

03

Score & render

XP math, level lookup, badge rules, and a self-contained HTML render. One command produces one file.

Engineers keep doing what they already do — log hours, send their usual emails. Nothing new to learn, nothing new to install.

Skills framework

Eight skills. Everyone graded on the ones they own.

Skill universe

Coding Electronics Electrical Mechanical Assembly Testing Teamwork Management

ICs are graded on the first six plus Teamwork. Leads on the first six plus Management. A junior engineer is never penalized for not running meetings; a tech lead never gets a free pass on technical depth.

Motivation layer

Badges — not rankings.

Daily Reporter

Logged hours every workday this week.

Deep Focus

Spent 80%+ of the week on a single project.

Multi-skilled

Earned XP in 4+ skills this week.

Skill Up

Crossed a level threshold during the period.

Cross-Trainer

Earned XP outside their primary skill.

… extensible

Rules are plain Python — new badges are a one-line addition.

Engineers see their own growth, not a leaderboard. The team-coverage view is for the manager. The point is to celebrate trajectory, not produce a ranking.

KPI & performance review

No more end-of-year surprises.

Each engineer's performance review goals are baked into their dashboard card. Every week and every month, they see the exact KPIs they'll be graded on at the next review — and how they're tracking right now.

Weekly — tactical

"This week I gained X XP in Mechanical, Y in Testing. I missed Cross-Trainer because I didn't touch Electrical." Concrete, immediate, actionable.

Monthly — directional

"My target is L5 in Mechanical by Q3. I'm 18k XP away. At my current rate I'll arrive 3 weeks early." A trajectory, not just a snapshot.

Quarterly — the review

No surprises. The annual review draws from the same data the engineer has been seeing all year. The conversation is about direction, not about what happened.

What lives on each engineer's card

▸Next-review focus skills — the 2–3 skills the manager has flagged as priority growth areas.
▸Target levels & dates — e.g. "L5 Mechanical by 2026-09-30."
▸Specific growth notes — "Drive system-level decisions, not just component-level." Manager-authored.
▸Strengths to keep leaning on — what's already working, so it doesn't get neglected.
▸Trajectory line — weekly XP trend on the focus skills, with target marker.
▸Next review date — visible countdown so it's never abstract.

The dashboard becomes a continuous performance review — engineers always know where they stand, where they're going, and what they need to work on. The annual review stops being a verdict and becomes a checkpoint.

What can go wrong

Known issues — surfaced, not hidden.

1. Classifier noise

Keyword matcher over-tags. "Install printer" should not earn Coding XP. Inflates some skill totals.

2. Cumulative vs period XP confusion

The level number reflects lifetime XP; the green delta reflects the current week. Easy to misread.

3. Review notes are placeholders

"Strengths" and "growth areas" must come from the manager. AI-generated content here is not honest data.

4. Email signal is weak

Engineers don't email structured EOD reports. Email is decorative, not load-bearing — the timesheet is the truth.

5. Logging discipline is the floor

If an engineer skips logging, they look idle. The dashboard is only as honest as the timesheet.

6. Gaming the system

Padding entries to chase XP is possible. Mitigated by manager review — XP supplements judgment, doesn't replace it.

Mitigations & roadmap

How we close each gap.

1

Swap the keyword classifier for Claude Sonnet

Cached, batched LLM classification understands "URDF" and "MoveIt" without manual keyword maintenance. Cuts noise dramatically.

2

Re-label "Lifetime XP" vs "This week"

UI fix — rename labels and split into two visually distinct elements. No misreads.

3

Manager-authored review fields

Strengths / growth / rating come from a structured input the manager fills in — not generated. Treated as first-class data.

4

Logging-discipline flags (manager-only view)

Surface "missed N days this month" as a manager-side signal, not an engineer-facing public stat.

5

History snapshots for trend charts

Append weekly snapshots to a small JSONL so monthly views show real week-over-week deltas instead of just totals.

In short

A continuous, honest view of how each engineer is growing.

Built on data the team already produces. Designed to supplement manager judgment, not replace it.
