What's actually new here

Each component exists somewhere. The combination doesn't.

A survey of the adjacent tools shows that every part of this dashboard already exists in industry — but no single product bundles them for a multi-disciplinary engineering team.

The unusual move is using timesheet hours as the source signal for a growth-tracking system — in a hardware-heavy team where git logs don't capture the work. That combination is what doesn't exist commercially.

Design choices that already dodge the failure modes

Four decisions that defuse most of the case against.

Badges, not rankings

Defuses: the Disney electronic-whip dynamic, the Omnicare leaderboard backfire. There is no public ordering of engineers. No one is "ahead" or "behind" anyone else. The unit of comparison is the engineer against their own past, not against their peers.

Radar tracks breadth, not output

Defuses: the hours-equal-value problem. The skill radar rewards cross-training — the exact behavior billable-hour systems punish. A senior who unblocks teammates earns Teamwork XP. A generalist's wide radar reads as strength, not lack of focus.

Same data for engineer and manager

Defuses: the "Big Brother" reaction that killed Omnicare. The dashboard is not a private surveillance tool the manager uses on the engineer. It's a shared mirror — both parties see exactly the same numbers, at the same time. Surveillance becomes transparency.

Hours are actually meaningful for hardware work

Defuses: the "hours don't measure software value" critique. For mechanical, electronics, assembly, and testing work, there is no `git log` substitute. Hours-on-task is closer to truth here than it is in software, and meaningfully closer than self-assessment.

Guardrails to add — or never remove

Four rules that have to stay in place.

The design choices above only hold if the rules below stay enforced. Each rule corresponds to a documented failure mode — remove the rule and the failure mode arrives.

1

XP stays decoupled from compensation. Forever.

The instant XP touches bonuses or raises, the system becomes the billable hour. This is the single hardest rule to hold because it will feel reasonable to violate. Don't.

2

Cap XP per week.

A weekly XP ceiling (e.g. 40–50 logged hours) breaks the "more hours = more progress" loop and removes the incentive to pad. Working weekends doesn't accelerate leveling; it just exhausts the engineer.

3

Levels require objective evidence, not just hours.

Crossing a level threshold is a candidacy for promotion, not the promotion itself. A real level-up requires a build shipped, a checkoff completed, or a peer/manager sign-off. Hours alone never lift a level.

4

Engineers control radar visibility.

Each engineer chooses whether their skill radar is private, manager-shared, or team-visible. Public-by-default is the path to the Disney scoreboard. Private-by-default with opt-in sharing is the path to a tool engineers actually want to use.

Bottom line

It's a mirror, not a dial.
The risk isn't the dashboard. It's the first leadership conversation that turns it into one.

Build it as a tool engineers consult to see themselves grow. Hold the line that it never becomes the tool by which they are graded. If both halves of that sentence stay true, the dashboard is the untapped good idea. If either half slips, it's the next billable hour.
